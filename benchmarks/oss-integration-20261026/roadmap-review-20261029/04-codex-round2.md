**큰 방향에 동의합니다.** 5명 평가자 요건은 철회하고, 우선 목표를 “정해진 용도에서 소유자가 수용하는 편집 가능 자산”으로 좁히겠습니다. 이번 검토에서는 파일을 수정하거나 테스트를 실행하지 않았습니다.

1. **평가자: 내부 개발용으로는 제안을 수용합니다.** 다만 75% 일치가 사람 평가를 대체한다는 인증은 아닙니다. 60개 판단을 예컨대 보정 20개·잠금 검증 40개로 나누되, 같은 물체·제품군이 양쪽에 들어가지 않아야 합니다. 검증 40개 중 30개 일치의 95% 구간은 약 60–86%여서 불확실성이 큽니다.

   모델·프롬프트·합의 규칙을 먼저 고정하고, 생성자 정보를 숨겨 독립 판정하게 하십시오. A/B 순서를 바꾸고 동점을 허용하며, 다수 클래스만 고르는 기준선과 범주별 오류도 확인해야 합니다. 이후 **무작위 20% 점검에 불일치 사례 검토를 추가**하되, 두 표본의 통계는 분리합니다. 새 범주·judge 변경 시 재검증합니다.

   최소 인간 설계는 **소유자 1명 + 일부 재평가로 자기 일관성 확인 + 최종 성공 판정의 직접 평가**입니다. 모델 패널은 개발 선별을 확장합니다. 일반 사용자 수용성 주장은 독립적인 목표 사용자 평가가 생길 때까지 보류합니다. 멀티모달 연구에서도 쌍대비교와 절대점수 평가의 인간 일치도가 달랐습니다. [MLLM-as-a-Judge](https://proceedings.mlr.press/v235/chen24h.html)

2. **전용 생성기 없이 진행할 수 있습니다.** 지원하는 주장은 “선정한 분포에서 참조 충실도·편집 계약·소유자 수용 기준을 충족한 비율”입니다. 경쟁 제품과의 동등성·우월성은 주장하지 않습니다. 따라서 1차의 경쟁 비열등성 문턱은 보류합니다.

   정답 렌더와의 쌍대 선호만으로 절대 수용성을 얻지는 못합니다. 각 생성물에 별도로 “이 용도에 사용 가능/수정 필요/불가”와 결함 이유를 기록해야 합니다. 사진과 정답 GLB가 충돌하는 외관은 사전에 평가 대상을 지정하고, 사진으로 보이지 않는 형상은 정확성 주장에 포함하지 않습니다.

3. **기능 노출 실험의 병행에 동의합니다.** 기존 dev에서 실행하면서 새 평가 세트를 준비하면 됩니다. 동일 모델·입력·호출 예산으로 비교하되, 연산·부품 수·재질 안내를 함께 바꾸면 결론은 “안내 묶음의 효과”입니다. 특정 연산이 원인이라는 주장은 추가 분리가 필요합니다.

   시간을 더 쓴 Claude IR은 **도달 가능한 품질의 사례이지 엄밀한 상한이 아닙니다.** 소유자가 전부 손으로 작성할 필요는 없습니다. 대표 결함 3–5개에서 부품 구성과 핵심 형상을 검토·수정하면 충분합니다. 작성 실패만으로 엔진 표현 불가능을 판정하지 말고, 최소 구현 사례나 명시적 제약으로 확인해야 합니다.

4. **범주 통합에 동의합니다.** CHAIR·SOFA·BED를 새 평가 세트에 포함하되, 상품명보다 실제 구조로 강체·곡면·쿠션/직물 층을 나누겠습니다. 의자나 침대가 모두 유기적 형상은 아닙니다. 전체 평균과 층별 결과를 함께 보고합니다.

수렴한 실행 순서는 다음과 같습니다.

| 순서 | 작업과 성공·중단 규칙 |
|---|---|
| 1 | **측면 사진 재검증 종료.** 기존 프로토콜·V1–V4 유지. V1/V2 실패면 요청군 개선 주장을, V4 실패면 선별 능력 주장을 중단합니다. V3는 동등성 증명이 아닙니다. |
| 2 | **평가 기반 구축과 기능 노출 실험 병행.** 별도 보정 표본과 새 test 36개 이상, 절반 이상 ABO 밖 일반 사진, 물체당 3회 생성을 유지합니다. 기능 노출 성공은 중요 특징 충족률 **+15%p 이상, 짝지은 95% CI 하한 >0, 중대 악화 ≤5%**입니다. dev에서 효과가 없으면 안내 확장을 중단합니다. judge의 75%는 잠정 선별 기준으로 낮추고, 최종 판정은 소유자가 합니다. |
| 3 | **부품 관계 수치 공유.** 관계 오차가 주요 원인일 때 진행합니다. 중요 특징 위치·크기 오차 **P90 ≥25% 감소**, 새 시점 중대 악화 ≤5%, 토폴로지 결함 0. 원인 진단이나 dev 개선이 없으면 중단합니다. |
| 4 | **B3 사진 투영.** 고정 형상에서 B4와 비교하고 카메라·가시성·UV·노출 보정을 평가합니다. 1K·여러 조명에서 소유자 블라인드 선호율 **95% CI 하한 >50%**, 민무늬 중대 악화 ≤5%, UV 결함 0. dev에서 지각적 개선이 없으면 중단합니다. |
| 5 | **한 용도 납품 완결.** 새 자산 12개에서 이름 지정 편집·저장·Blender 재수출 **12/12**, 비대상 부품·재질·메타데이터 보존, 필수 게이트 통과, 수정 시간 중앙값 ≤15분. 재현되는 손상은 해결 전 범위 확장을 중단합니다. |

최종 test는 후보를 고정한 뒤 평가합니다. 결과를 보고 방법을 바꾸면 다음 확증에는 새 test를 사용합니다. 반복 생성·시점·judge 투표를 독립 표본으로 세지 않고 물체 단위로 분석합니다. 또한 **≤5%는 현재 표본의 관측 기준**입니다. 36개에서 악화가 0건이어도 모집단 악화율 ≤5%를 입증하지는 못합니다.

Blender의 미사용 데이터 정리와 보존 검증은 위 작업과 병행합니다. Unity와 전자 실물 근거 확대는 해당 납품 용도가 정해질 때 진행합니다.

다음 1–2일의 구체적인 순서는 이렇습니다.

1. 재검증 프로토콜 해시와 실행 상태를 확인합니다. 현재 `test-sonnet-r2` 산출물이 있으므로, 점수를 열기 전에 완료 여부와 재개 방식을 확인하고 **누락분만** 실행합니다.
2. 기존 기준으로 재검증 결론을 닫습니다. 동시에 첫 납품 용도·수용 판정표·중대 악화 정의를 고정합니다.
3. 기존 dev용 확장 안내와 대표 결함 3–5개를 준비하고 동일 예산 비교를 시작합니다. 새 평가 후보는 제품군 중복을 제거해 보정용과 test로 분리합니다.
4. 첫 보정 판단을 수집하고 Blender 정리 범위를 확인합니다. 코드 변경 후에는 `npm test`, `npm run benchmark`, `npm run build`와 해당 보존 검증을 실행합니다.

소유자만 결정할 사항은 **첫 고객 용도와 허용 수정 시간·수용률**, 평가에 투입할 본인 시간과 비용 상한, 향후 독립 사용자 평가 여부입니다. 전용 생성기 비교를 나중에 원한다면 평가용 예외 허용·계정·비용·약관 수용도 소유자가 결정합니다. 그 결정 없이도 위 계획은 진행할 수 있습니다.
