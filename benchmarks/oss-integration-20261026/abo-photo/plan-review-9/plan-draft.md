# 9차 계획 초안 (2026-10-27)

## 진단 (8차 test 30건, 이미 본 데이터)
- 원래 다음 후보 1번은 "가는 구조 어휘"였다. 그런데 하위 6건(선풍기·램프·조명, IoU 0.37~0.56)을 보면 구조는 대체로 맞다. F-score@5%가 1.00이고 높이·가로 오차가 0~5%인 항목이 여럿이다.
  예: B082XLWBDL 실링팬은 IoU 0.515, F5 1.00, 크기 오차 0/0/1%.
- 낮은 IoU의 주원인은 160px 래스터에서 1~2px 굵기의 막대·날개 위치가 조금만 어긋나도 IoU가 무너지는 것이다. 날개의 기울기·위상, 기둥의 xz 오프셋이 그 예다.
  어휘(tube가 이미 있다)보다 지표의 민감도 문제로 본다. 그래서 "가는 구조 어휘"는 근거가 약하다.
- 남은 실제 오차는 깊이(z)축이다. 정면 사진 한 장으로는 두께를 볼 수 없다. 예: 벽등 z 0.45, 토치어 z 0.36, 서랍장 z 0.20, 책상 z 0.19.
- 상품명 치수를 지우면 가로·깊이 오차가 중앙값 5.6%, p75 12.1%이고 이번 오차의 대부분은 깊이다.

## 제안: 2장 입력(정면 프레임 0 + 턴테이블 90° 프레임 18)
목표 정합성: evidence-pack 계약상 사진 여러 장은 정상 입력이다. LLM만 쓰고 피팅은 쓰지 않는다(8차에서 실사진 피팅이 해로웠다).

- 조건: 상품명 치수 제거(사진만의 정직한 조건)와 리스팅 높이 제공. 피팅 끔. Sonnet 주 모델, Haiku 보조.
- 팔(arm) 구성. 모두 같은 항목에서 짝지어 비교한다.
  - A1: LLM 1장. 8차 explore-strip 조건과 같다.
  - A2: LLM 2장. 같은 가이드에 "두 번째 사진은 같은 제품을 수직축으로 90° 돌려 찍은 것"이라는 한 줄을 더한다.
  - B1: 정면 실루엣 돌출(8차와 같음).
  - B2: 두 실루엣 시각 헐(visual hull). 정면 실루엣을 Z로 돌출한 것과 측면 실루엣을 X로 돌출한 것의 교집합이며, 리스팅 높이로 스케일을 정한다. LLM 없이 2장에서 얻을 수 있는 강한 기준선이다.
- 데이터
  - dev: 8차 dev 10건을 재사용한다(이미 노출됨). 프롬프트 한 줄을 확정하는 데만 쓴다.
  - test: 8차 selection의 같은 시드 순서에서 55번 이후 미사용 항목 30건을 새로 뽑는다.
  - 8차와 같은 실행 시 제외 규칙(see-through, mask share)을 적용한다. 8차에 쓴 모든 항목과의 GLB 중복을 정점·면 수와 extent로 검사한다.
  - 이미지를 보기 전에 목록을 고정한다.
- 지표: 8차와 같은 compareMeshShapes(8방위 20°, IoU, Chamfer/diag, F2/F5, extent). 깊이축 오차를 따로 보고한다. 가는 구조는 IoU보다 F-score와 Chamfer로 해석한다.
- 사전 등록 기준(test, Sonnet)
  1. depth-error: A2−A1의 짝지은 가로·깊이 오차 차이. 중앙값 < 0이고 bootstrap 95% CI 상한 < 0.
  2. no-shape-loss: A2−A1 IoU 중앙값 ≥ −0.01.
  3. beats-hull: A2−B2 IoU 중앙값 > 0이고 CI 하한 > 0.
  4. absolute: A2 가로·깊이 오차 중앙값 ≤ 5%, p75 ≤ 10%.
- 비용 추정: Sonnet 30건 × 2팔이 약 1.6달러, Haiku는 약 0.15달러.

## 알려진 위험
- 턴테이블 프레임마다 크롭과 확대가 달라 두 사진의 축척이 다르다. LLM에게 그렇게 알린다. B2는 각 실루엣 높이를 리스팅 높이에 맞춰 정규화한다.
- 회전 방향(+90°인지 −90°인지)을 모른다. 대칭 제품이 많아 깊이 추정에는 영향이 적다. 비대칭 제품은 좌우가 반전될 수 있지만 yaw 탐색은 반사를 다루지 못한다.
- 실제 사용자가 직각 측면 사진을 줄 것이라는 가정은 낙관적이다. 이번 결과는 "두 번째 시점의 상한"으로 읽는다.
