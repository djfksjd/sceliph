# Sceliph 8차 고도화 계획 초안 (2026-10-27, 반대 검토 대상)

## 배경 (현재 측정 상태)
- 목표: LLM만으로(전용 3D 생성기 금지) 전용 3D 생성 모델 수준의 실무 품질. 현재 추정 약 30%(겉보기 품질만 15~20%). 측정값 아님.
- 사진 경로(1~7차, 미커밋, 브랜치 engine/oss-integration-20261026):
  MoGe-2 ONNX 점지도 → 앵커 1개로 미터 보정 → 궤도 카메라 초기화 → CMA-ES 실루엣+부품마스크+깊이 손실로
  카메라만(1단계) → 카메라+형상(2단계) 피팅. LLM(claude -p, Haiku/Sonnet)이 사진 보고 AssemblyIR + 대략 시점 작성.
- 7차 사전 등록 검증(합성 Blender CG 5장면, 새 응답 20건, protocol-v2.json):
  크기 오차 중앙값 LLM 8.1% → 최종 5.0%, 10% 이내 76% → 89%. 그러나 "2%p 넘게 악화 ≤ 2/20" 기준 실패(5/20).
  악화 형태: 상자 높이↔깊이 맞바뀜(150→168, 200→168), 기둥 반지름 -5%, 책장 다변수 드리프트.
  수락 게이트(손실 감소율, 변수당 감소율, IoU)는 20건 중 16건 수락 → 거의 무력.
- 한계: 무늬 없는 합성 CG, 화각 알려 줌, 부품 마스크 정답(oracle), 실제 사진 검증 없음, 전용 모델과 블라인드 비교 없음.
- quality:gate 실패 원인(전자 부품 근거 52/90, 같은 입력 시각 비교 미확립, Unity 보고서 없음, Blender raw re-export)은 그대로.

## 이번 차수 목표
"측정된 개선이 실제 사진에서도 유지되는가"를 처음으로 정답 기반으로 확인하고, 피팅이 맞는 IR을 해치는 문제를 줄인다.

## 단계

### 0. 진단 (합성 개발 데이터만, 새 LLM 호출 없음)
- 0a 손실 최솟값 편향 측정: 정답 IR에서 시작해 되돌리기 없이 강제로 최적화 → 정답에서 얼마나 떠나는지.
  5% 바닥이 손실 함수의 편향(래스터 160px, Blender 안티에일리어싱 마스크, MoGe 깊이 편향, 둥근 모서리)인지
  최적화 문제인지 가른다. 래스터 320, 깊이 가중 0/2, 경계거리 가중 변형 비교.
- 0b LLM 값 중심 형상 사전분포(MAP): 형상 변수마다 log 공간 가우시안(중심 = LLM 값, σ ∈ {0.05, 0.1, 0.2}).
  개발 데이터 30건(6차 10건 + 7차 테스트 20건, 이제 개발용으로 전환)에서 σ와 가중치 선택.
  목표 함수: 2%p 악화 건수 최소화, 중앙값 유지.

### 1. 합성 재검증 (사전 등록 protocol-v3)
- v3 고정 후 새 응답 20건(2회 × 5장면 × Haiku/Sonnet). 기준은 v2와 동일.

### 2. 실제 사진 검증 (ABO, 처음)
- 데이터: Amazon Berkeley Objects(CC-BY-4.0). 360° 턴테이블 사진(spins, 72장) + 아티스트 3D GLB(미터 단위 extent).
  S3 공개 접근 확인됨(3dmodels 7,953개, spins 58.6만 행). 개발에 노출된 3건(램프, 선풍기, 러그)은 제외.
- 선정: 이미지를 보기 전에 규칙과 시드를 고정. 하드서피스 범주(가구·조명·수납·소형 가전), spin과 3D 모델 둘 다
  있는 항목, 노출 원장에 없는 항목에서 무작위 8개.
- 입력: spin 프레임 1장(인덱스 0) + 알려진 치수 1개(GT 모델 높이, 데이터시트 값 역할). 화각 모름(MoGe 추정 + 초점 피팅).
  마스크: SAM 자동 물체 마스크만(부품 마스크 없음). 부품 마스크는 선택 실험.
- 채점(정답 사용은 채점에만):
  (a) 전체 크기(x/y/z extent) 오차 vs GT,
  (b) 새 시점 실루엣 IoU: 보류한 spin 프레임(+90°, +180°, +270°)에서. 각 프레임 카메라는 GT 메시로 카메라만 피팅해 구함,
  (c) 대칭 Chamfer(GT 대각선으로 정규화), yaw 탐색 정렬.
  비교 대상: LLM IR 그대로 vs 피팅 결과.
- 기준(사전 등록): 피팅 결과가 LLM IR보다 새 시점 IoU에서 8개 중 6개 이상 우세, 전체 크기 오차 중앙값 ≤ 10%.

### 3. 정리
- 문서·증거·검증(check/test/benchmark/build).

## 미루는 것과 이유
- TRELLIS.2 등과 블라인드 비교: CUDA 필요(이 Mac에서 불가), 사용자 결정 대기 항목.
- 사진 텍스처 투영·굽기: 9차 후보(기존 reference-projection.ts는 캐릭터 단일 방향용).
- Anny 인체 템플릿, replicad BREP: 범위 밖.
- gate 원인: 전자 부품 실측(물리 벤치 필요), Unity 설치 필요.
