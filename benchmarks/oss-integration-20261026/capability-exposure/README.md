# 로드맵 2b: 기능 노출 실험 (dev, 탐색, 2026-10-29)

같은 모델(Sonnet), 같은 입력, 같은 호출 예산으로 9b 개발 10건을 비교했다. 반복은 각 1회다.
- **G0**: 9b 안내문. 연산 7개, 부품 2~16개, 색·거칠기·금속성만 안내한다.
- **G1**: `protocol-dev-g1.json`. booleanCSG, implicitSurface, 재질 마감(surface·clearcoat·투과·sheen 등), 부품 2~40개를 추가했다.
- 실행 스크립트는 `scripts/abo-capability-eval.ts`다. abo-multiview-eval에 Manifold 초기화만 더했다.

|---|---|---|---|---|
| a1 | −0.046 | 3 / 6 | −0.006 | +0.013 |
| a2 | −0.031 | 2 / 7 | −0.018 | +0.001 |

- **잡음 기준**: 9b test에서 같은 안내문으로 반복 1과 2를 비교하면, 항목별 F@2% 차이 중앙값이 0.054이고 최대 하락은 −0.156이다. 1회 비교라서 항목별 차이는 대부분 잡음 범위 안이다.
- 두 팔을 합치면 개선 5, 악화 13이다. 잡음 범위를 넘는 하락도 있었다(a2 B082XCPNH5 0.93→0.44, a1 B07B4SB2D9 0.89→0.25, booleanCSG 사용).
- **연산 사용**: booleanCSG는 3건에서 썼다. implicitSurface는 한 번도 쓰지 않았다. 재질 마감은 모든 부품에 붙었다. 부품 수는 가구에서 늘었다(15→29, 12→25).
- 형상 지표는 재질 마감 효과를 재지 못한다. 마감의 외관 효과는 텍스처·외관 작업에서 따로 평가한다.

## 판정 (사전 합의한 중단 규칙)
dev에서 형상 개선이 없고 오히려 나빠지는 쪽으로 기울었다. 그래서 **형상 연산 안내 확장은 중단한다.** 형상 쪽에서 9~16차 수치가 7연산 안내에 묶여 있었다는 우려는 이 표본에서는 지지되지 않았다. 재질 마감 안내는 외관 평가에서 다시 다룬다.

## 부수 발견: 엔진 버그 수정
G1 준비 중 implicitSurface가 표면이 격자점에 정확히 닿는 경우(예: 타원체 극점)에 면적 0 삼각형으로 컴파일에 실패하는 버그를 찾았다. 반올림된 치수에서 흔히 생긴다.
- 수정(`src/engine/implicit-surface.ts`): 표면에서 셀의 1e-6 안쪽 샘플은 바로 바깥으로 취급한다.
- 회귀 테스트: `tests/implicit-surface.test.ts`
